# Memory Books neutral Status patch — Project Context and Handoff

## How to use this document

`CONTEXT.md` is this project's handoff/reference document for future chats that do not have access to the original conversation history. Use it to orient yourself quickly, then inspect the relevant current files before making a change; do not rely blindly on this summary. When significant architecture, files, data contracts, or user-facing features change, update `CONTEXT.md` in the same change so it remains an accurate reference.

Update this document after every project change or file addition, including small fixes, documentation, configuration, assets, renames, and removals. Refresh the affected sections in the same change; do not leave the update for a later task.

## 1. Project overview

This is a local modification of Aiko Hanasaki's SillyTavern-MemoryBooks, upstream commit `0e9bdf9`, version 9.2.3. It is a browser extension for chat summaries, tiered memories, lorebooks, and persistent Side Prompt trackers. The approved task replaces the Status tracker's romance/sexual-attraction factors and numerical relationship ladder with factual relationship descriptions, and replaces story suggestions with observations and unresolved questions. Other tracker and memory behavior must remain intact.

## 2. File and folder structure

- `index.js`, `sidePrompts.js`: extension initialization, commands, Side Prompt assembly, provider calls, preview, queue, and persistence.
- `sidePromptsManager.js`, `sidePromptsPopup.js`: saved prompt documents and editor UI.
- `relationshipPromptDefaults.js`: authoritative neutral Status instructions and six report sections in English and eleven other locales.
- `relationshipPromptMigration.js`: exact field/block recognition and pure migration; detection of customized legacy wording requiring review.
- `relationshipPromptLegacy.js`: generated SHA-256 recognition registry, containing no old generation instructions.
- `bin/update-relationship-prompts.js`: synchronizes Status locale JSON, downloadable packs, and the recognition registry. Run with Node from the repository root.
- `test-fixtures/legacy-status-prompts.json`: upstream legacy definitions retained solely to verify migration; not imported by runtime code.
- `relationshipPromptMigration.test.js`, `relationshipPromptIntegration.test.js`, `test-support/extension-harness.js`: pure migration tests and real extension modules with mocked SillyTavern/provider boundaries. The latter uses Node's experimental VM modules.
- `qa/live-status-results.json`: synthetic scene and real-provider output evidence; contains no credentials or personal chats.
- `autocreate.js`, `autocreate.test.js`: auto-created chat lorebook binding and regression coverage for immediately updating its assignment indicators.
- `qa/lorebook-save-results.json`: live summary/Side Prompt preview-save investigation, binding-indicator verification, and profile-control test scope.
- `locales.js`, `locales/*.json`, `resources/SidePromptTemplateLibrary.json`, `resources/prompts/side-prompts-*.json`: runtime translations and importable prompt packs.
- `manifest.json`: loads generated `index.build.js` and `style.build.css`. `build.ts` uses Bun and externalizes SillyTavern imports.
- `readme.md`, `USER_GUIDE.md`: user documentation; this document is the maintainer handoff.

## 3. Existing features

Memory creation and consolidation, clipping, lorebook management, Side Prompt sets, manual/interval/after-memory execution, previews, regeneration, and rollback belong to upstream. Status is being changed to descriptive relationship dynamics, changes/evidence, trust/boundaries/communication, goals, observations/questions, and a factual summary. Romance remains reportable when supported by the story; no preferred relationship outcome is imposed.

## 4. Important implementation details

Prompt and response format are separate saved fields. `sidePrompts.js` appends the previous tracker entry, optional memories/additional context, scene text, and response format. Prior entries are included independently of the previous-memory count. Outputs are plain text, not parsed relationship scores. Regeneration uses the current template with saved scene/prior content. Prepared jobs retain their assembled prompt, so old queued jobs need to be restarted after installing the patch.

Side Prompts are stored in the user's `user/files/stmb-side-prompts.json`, separate from the extension code. Changing shipped defaults alone does not update existing saved templates. Migrations preserve template keys, names, settings, triggers, sets, and arbitrary custom text outside exact recognized legacy blocks. Before a migration write, the complete original document is saved under `stmb-side-prompts-before-neutral-status-<timestamp>-<id>.json`; the filename is retained in `relationshipPromptBackups`. Backup/save errors propagate outside the old recreate-defaults fallback. `js-sha256` is bundled for recognition because Web Crypto is unavailable on insecure LAN HTTP connections used by phones. Retired names may occur only in recognition logic, historical test fixtures, QA evidence, and explanatory documentation, never active defaults.

## 5. Rules and constraints

- Preserve all chats, characters, settings, lorebooks, snapshots, and unrelated extension behavior. Never use the global recreate-built-ins action for this patch.
- Keep upstream copyright/license notices and identify local modifications. No SillyTavern core changes are authorized or needed.
- New CSS rules require comments; no CSS change is currently needed.
- The user approved implementation and live API testing on the already-running local instance. Keys must stay hidden. The supplied installation is clean; the user's personal custom prompts are not present.
- Three pre-existing modifications in `bin/install-hooks.js`, `bin/postinstall.js`, and `hooks/pre-commit` must be preserved.
